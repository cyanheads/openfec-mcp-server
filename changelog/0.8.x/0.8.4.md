# 0.8.4 — 2026-09-23

## Added

- **`truncated`/`shown`/`cap`** enrichment on `openfec_search_contributions`, `openfec_search_disbursements`, `openfec_search_expenditures`, `openfec_search_coordinated_expenditures`, `openfec_search_filings`, and `openfec_search_candidates` (with `include_totals`) discloses when a page was bounded below the requested `per_page` to stay under a 100,000-byte response budget; `pagination.per_page` echoes the size actually applied. No fetched row is ever discarded — the cap lowers the upstream request itself. ([#29](https://github.com/cyanheads/openfec-mcp-server/issues/29))
- **`election_full`** on `openfec_search_expenditures`' `by_candidate` mode selects the full election period ending in `cycle` (4yr president, 6yr senate, 2yr house) instead of the two-year cycle alone; defaults to `true` (OpenFEC's own default), is echoed in `search_criteria`, and is rejected in itemized mode. ([#42](https://github.com/cyanheads/openfec-mcp-server/issues/42))

## Changed

- A committee record left nested on a row — a donor-as-committee `contributor`, a transfer's `recipient_committee`, or Schedule E/F's per-row `committee` on a page spanning committees — now renders in `content[]` as a compact name, ID, and one attribute line instead of a raw JSON dump; `structuredContent` keeps the full record. ([#35](https://github.com/cyanheads/openfec-mcp-server/issues/35))
- Null and empty fields are dropped at every depth from itemized, filing, candidate, and totals rows — lossless, since an absent field and a null one say the same thing; `false` and `0` are kept as the facts they are.
- `openfec_search_candidates` with `include_totals` and no `cycle` or `election_year` set now returns 5 candidates per page instead of up to 100, since an all-cycles candidate's totals span every cycle it filed in.
