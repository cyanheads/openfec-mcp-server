# 0.8.4 — 2026-09-23

## Added

- **`truncated`/`shown`/`cap`** enrichment on `openfec_search_contributions`, `openfec_search_disbursements`, `openfec_search_expenditures`, `openfec_search_coordinated_expenditures`, `openfec_search_filings`, and `openfec_search_candidates` (with `include_totals`) discloses when a page was bounded below the requested `per_page` to stay under a 100,000-byte response budget; the page-based tools echo the size applied as `pagination.per_page`. No fetched row is ever discarded — the cap lowers the upstream request itself. ([#29](https://github.com/cyanheads/openfec-mcp-server/issues/29))
- **`election_full`** on `openfec_search_expenditures`' `by_candidate` mode selects the full election period ending in `cycle` (4yr president, 6yr senate, 2yr house) instead of the two-year cycle alone; defaults to `true` (OpenFEC's own default), is echoed in `search_criteria`, and is rejected in itemized mode. ([#42](https://github.com/cyanheads/openfec-mcp-server/issues/42))

## Changed

- A committee record left nested on a row — a donor-as-committee `contributor`, a transfer's `recipient_committee`, or Schedule E/F's per-row `committee` on a page spanning committees — now renders in `content[]` as a compact name, ID, and one attribute line instead of a raw JSON dump; `structuredContent` keeps the full record. ([#35](https://github.com/cyanheads/openfec-mcp-server/issues/35))
- A `per_page` above a tool's cap now returns fewer rows per page than requested: at most 30 from itemized contributions and disbursements; 60 from itemized expenditures with `committee_id`, 30 without; 80 from coordinated expenditures with `committee_id`, 25 without; 65 from filings; and, from a candidate search with `include_totals`, 35 when `cycle` or `election_year` scopes the totals and 5 when they span every cycle — so that last search returns 5 candidates even at the default `per_page` of 20. The page-based tools count `page` numbers at the capped size. ([#29](https://github.com/cyanheads/openfec-mcp-server/issues/29))
- Null and empty fields are dropped at every depth from itemized, filing, candidate, and candidate-totals rows — lossless, since an absent field and a null one say the same thing; `false` and `0` are kept as the facts they are, and array elements keep their positions. ([#29](https://github.com/cyanheads/openfec-mcp-server/issues/29))

## Fixed

- Itemized `openfec_search_contributions`, `openfec_search_disbursements`, and `openfec_search_expenditures` no longer return a `next_cursor` — or, at a capped page size, `truncated` — from a full page that ends exactly at the last row of an exactly counted result. The cursor now carries the running row count, so an exact count ends the walk on any page, not only the first. ([#29](https://github.com/cyanheads/openfec-mcp-server/issues/29))
