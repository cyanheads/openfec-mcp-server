# 0.8.2 — 2026-09-22

## Fixed

- **Exhausted pagination positions** — a page past the last page, a keyset cursor replayed past the last row, or an `openfec_search_legal` `from_hit` past the end of the matching documents now report the position and preserve the total instead of a "No results found" zero-match notice. `openfec_get_committee_totals` mode `single` no longer throws `committee_totals_not_found` for a page past the end of a committee's real totals. ([#28](https://github.com/cyanheads/openfec-mcp-server/issues/28))
- **`openfec_search_legal`** rejects `from_hit + hits_returned` above the upstream 10,000-result window before dispatch, as `legal_window_exceeded`, instead of surfacing OpenSearch's generic 400. ([#36](https://github.com/cyanheads/openfec-mcp-server/issues/36))
- **`is_count_exact`** now flows through to `count_is_approximate` on `openfec_search_contributions`, `openfec_search_disbursements`, `openfec_search_expenditures` (itemized mode), and `openfec_search_filings` — the four tools whose upstream endpoints report an estimated count on large result sets. `format()` renders `≈N total (approximate)`; the removed static "may be approximate" caveat on `count` was wrong in both directions. ([#40](https://github.com/cyanheads/openfec-mcp-server/issues/40))
