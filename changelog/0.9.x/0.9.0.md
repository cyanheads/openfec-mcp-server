# 0.9.0 — 2026-09-24

Breaking: legal search results no longer carry `dispositions`, large legal documents withhold arrays until requested with `array`/`offset`, and legal search inputs upstream silently ignored now fail as `filter_not_valid_for_type` or `invalid_citation`.

## Changed

- **`openfec_search_legal` results replace `dispositions`** with `disposition_count` and `disposition_categories`, as `documents` already was; `openfec_get_legal_document` returns the full array. ([#30](https://github.com/cyanheads/openfec-mcp-server/issues/30))
- **`openfec_search_legal` holds each response to 100,000 bytes** by admitting whole results round-robin across document types. A page that held results back sets `truncated`, `shown`, and `nextFromHit` — the `from_hit` that continues each type, re-called with that `type`. ([#30](https://github.com/cyanheads/openfec-mcp-server/issues/30))
- **`openfec_get_legal_document` bounds large records**: one over 100,000 bytes returns its scalar fields and the arrays that fit, listing the rest in `withheld`. New `array` and `offset` inputs page one array by entry through `slice`; new errors `array_not_in_record` and `offset_without_array`. ([#30](https://github.com/cyanheads/openfec-mcp-server/issues/30))
- **`filter_not_valid_for_type`** on `openfec_search_legal` rejects a citation, penalty bound, `respondent`, `ao_number`, or `case_number` sent with a `type` it doesn't filter, filters no single type accepts together, and — on `murs`/`adrs` — a citation combined with `case_number`, `respondent`, a penalty bound, or an `open_date`/`close_date` bound. ([#31](https://github.com/cyanheads/openfec-mcp-server/issues/31))
- **Untyped `openfec_search_legal` with type-specific filters** returns only the types every supplied filter applies to, and `total_count` sums those types rather than counting the others unfiltered. ([#31](https://github.com/cyanheads/openfec-mcp-server/issues/31))
- **`invalid_citation`** on `openfec_search_legal` rejects a citation that isn't one `<title> U.S.C. <section>` or `<title> CFR <part>.<section>` value (`USC`, `C.F.R.`, `§`, and subsection suffixes such as `30104(g)` accepted), including a value holding a second citation. ([#49](https://github.com/cyanheads/openfec-mcp-server/issues/49))
- **README capability reference rewritten for every tool**, covering the legal tools' filter routing, citation form, and response budget; `docs/design.md` records those as decisions 17–20.

## Fixed

- **`regulatory_citation` and `statutory_citation` now filter MURs and ADRs** — sent as `case_*` citations for `murs`/`adrs` and `ao_*` for advisory opinions, instead of `ao_*` for every type. ([#31](https://github.com/cyanheads/openfec-mcp-server/issues/31))
- **Legal search highlights** drop upstream's `<em>`/`</em>` match markup on both surfaces, leaving every other character as sent, and render one per line in `content[]`. ([#32](https://github.com/cyanheads/openfec-mcp-server/issues/32))
- **Nested legal fields render as text** in `content[]` instead of raw JSON — participants, entities, subjects, the archived-MUR subject tree, both citation shapes, advisory-opinion citation lists, and commission votes — and an archived MUR is headed by its `mur_name`; `structuredContent` is unchanged. ([#47](https://github.com/cyanheads/openfec-mcp-server/issues/47))
